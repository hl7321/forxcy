# 星野坐标访客体验改版设计规格

日期：2026-08-29  
状态：设计已确认，等待书面审核；尚未开始实现

## 1. 目标

将现有的实时位置查看网站改造成一个只面向“访客”的克制型私人入口。网站同时承载一封公开信和一个受密码保护的单向位置查看功能。它需要让访客感到自由、舒适、可信，而不是被要求回应或承受情绪压力。

成功标准：

- 访客进入后立即理解自己可以“读一封信”或“直接查看位置”。
- 首次访问自然注意到信件，但任何时候都可以跳过。
- 再次访问不会被迫重复阅读信件。
- 信件与过场有独立内容配置，后续修改文字不需要改动布局和动画代码。
- 位置查看继续由服务器端密码验证保护，现有定位上报和地图能力保持可用。
- 网站不请求访客定位，不发送访问通知，也不加入访问统计。

## 2. 受众与体验原则

唯一预期访客是用户的前女友，双方已经分开三年。第一版不表达“重新靠近”或复合诉求，只进行中性问候、说明网站用途并留下选择权。

体验原则：

1. **选择权优先**：两个入口始终存在，不以阅读信件作为查看位置的前置条件。
2. **克制而不冷淡**：保留温度，但避免爱心、复合暗示、强制回忆和情绪施压。
3. **功能可信**：清楚说明这是单向位置展示，不会读取访客位置，也不会通知站主。
4. **一次叙事，日常直达**：长过场只服务于信件路线，直接查看位置保持快速。
5. **内容与界面解耦**：用户可以独立修改文字，不能在内容配置中接触密码或视觉代码。

## 3. 范围与边界

### 包含

- 访客首页双入口。
- 公开信阅读页。
- 信件到密码页的叙事过场。
- 六位数字密码输入、分级提示、限流和成功反馈。
- 访客地图页的视觉重构与状态补全。
- 手机、桌面、键盘和减少动态效果适配。
- 搜索引擎屏蔽提示、错误状态和隐私说明。

### 不包含

- 不重写位置上报方式、坐标转换或 Leaflet 地图核心逻辑。
- 不新增账号体系、访客身份识别、聊天、回信、已读回执或通知。
- 不收集访客定位、设备指纹或分析数据。
- 不重构站主管理页；只修复改版引起的必要兼容问题。
- 不把公开信描述成加密或真正私密的内容。
- 不在第一版写入信件正文或过场文字；空内容是确认后的产品状态，不是遗漏。

## 4. 信息架构与访问流程

### 4.1 双入口

根页面永久提供：

- **读一封信**：公开访问，不需要密码。
- **查看位置**：需要有效的访客认证。

首次访问时，“读一封信”是视觉主入口，“查看位置”仍保持清晰可见。浏览器在读完信后写入 `letter_seen`。再次访问时仅交换两个入口的视觉优先级，不隐藏任何入口。

`letter_seen` 只保存在当前浏览器的 `localStorage`，不上传服务器，不代表访客身份，也不作为安全凭证。清除浏览器数据后，界面恢复首次访问状态。

### 4.2 路线

```text
首次或普通入口 → 双入口首页 → 公开信 → 叙事过场 → 密码或有效会话 → 地图
首次或普通入口 → 双入口首页 → 直接查看位置 → 密码或有效会话 → 地图
```

现有访客认证 Cookie 保持服务器端签名、HttpOnly 和 SameSite 属性。有效期内再次选择“查看位置”可以直接进入地图；Cookie 无效或过期时显示密码页。密码保护的是位置，不是公开信。

## 5. 页面与组件设计

### 5.1 双入口首页

- 第一视口直接表达“新的锚点”，不使用传统居中玻璃卡片或营销式大标题。
- 一个暖色坐标点作为唯一强焦点，两个入口围绕它形成清晰主次。
- 首次与再次访问仅改变入口权重，不改变文案和位置功能。
- 所有入口使用原生按钮或链接，支持键盘操作和可见焦点。

### 5.2 公开信

- 采用窄阅读宽度、较大行距和长留白，重点是阅读而不是装饰。
- 开场、正文、结尾分为独立区域；正文为空时完全省略，不显示占位文字。
- 页面始终提供返回首页和继续前往位置的明确操作。
- 阅读到结尾或主动点击“继续”后写入 `letter_seen`。

### 5.3 过场

- 过场是唯一的叙事型长动画，总时长约 3 秒。
- 信件文字退入夜色，留下暖色锚点；锚点沿坐标轨迹移动并最终成为密码区焦点。
- 过场文字从内容配置读取；配置为空时不渲染文字，动画节奏不留下空白停顿。
- 直接查看位置路线不播放长过场，只使用约 400 毫秒的常规状态切换。

### 5.4 密码页

- 延续现有六位数字输入方式，支持逐位输入、粘贴、退格和 Enter 提交。
- 密码提示位于输入区上方，反馈紧邻输入区并使用 `aria-live`。
- 错误使用轻微位移和暖灰色变化，不使用刺眼红色、连续抖动或警报图标。
- 提交期间禁止重复提交；网络错误保留当前输入并提供重试。
- 第三次后的个性化提示保持不变；第五次连续失败触发服务器现有限流，显示剩余等待时间。

### 5.5 地图页

- 地图继续作为页面主体，不用大卡片遮挡地图。
- 使用安静的灰蓝地图基底、深海军蓝功能层和单一暖色位置标记。
- 保留共享状态、电量、最后更新时间、停止共享提示、轨迹和退出查看。
- 超过 5 分钟未收到新位置时标记为“位置可能已过期”，但保留最后已知坐标和时间。
- 地图图块失败时显示可重试状态，不能让页面只剩空白区域。

## 6. 内容配置

新增一个公开的前端内容配置文件，只保存可编辑文案。它不包含访客密码、站主密码、签名密钥或任何定位数据。

建议字段：

```text
entry.greeting
entry.letterTitle
entry.letterDescription
entry.locationTitle
entry.locationDescription
letter.opening[]
letter.body[]
letter.closing[]
transition.lines[]
password.initialHint
password.failureHints[]
password.success
```

已确认内容：

- 开场：`你好，这是一封示例信。`、`欢迎来到这个新的锚点。`
- 正文：有意保持为空；空数组时不渲染正文区域。
- 结尾第一段：`这里只会展示站主的位置，不会获取访客的定位，所以站主看不到你在哪里。`
- 结尾第二段：`访客打开这个页面时，站主不会收到任何通知。`
- 结尾第三段：`这个站点主要用于演示单向位置分享。`
- 过场：有意保持为空；空数组时不渲染过场文字。
- 初始密码提示：`访问码是 6 位数字，请向站主索取。`
- 第一次失败：`访问码不正确，请再试一次。`
- 第二次失败：`访问码还是不对，注意位数。`
- 第三次及以后：`提示：访问码是 6 位数字。`
- 任意次数输入正确：`验证通过，正在进入地图。`

用户关于“访问码”的措辞是私人语境，不代表网站保存或展示真实手机解锁密码。

## 7. 视觉系统：“星野坐标”

视觉命题：不是浪漫星空，而是夜色中一个持续存在的坐标。页面应当暗而不压抑、温暖但不甜腻、自由并且克制。

### 7.1 色彩

- 主背景：从 `#172333` 经 `#111D2A` 过渡到 `#0C1622` 的深海军蓝。
- 主文字：`#F2EFE9` 柔和米白。
- 次要文字：`#9FADB8` 蓝灰。
- 暖色锚点：`#E8AD87`，只用于位置、焦点、成功和少量主要动作。
- 地图基底：约 `#DFE3E1` 的低饱和灰蓝；地图功能层继续使用深海军蓝。

不使用纯黑、大面积紫色、霓虹蓝、银河照片、流星雨或高密度闪烁星点。颜色不能成为状态的唯一表达方式。

### 7.2 字体与布局

- 信件使用系统中文衬线字体栈，形成书面阅读感。
- 按钮、密码和地图状态使用系统无衬线字体栈，保证清晰与加载稳定。
- 正文移动端不小于 16px，输入框不小于 16px，触控目标约 44px。
- 信件保持窄阅读宽度；桌面端扩大留白而不是拉宽正文。
- 控件以文字、细线和材料变化建立层级，不采用通用玻璃卡片阵列。

### 7.3 星空材料

- 星空由 CSS 或轻量 Canvas 生成，不依赖背景图片。
- 星点稀疏、分层且低对比，只允许很慢的有限漂移。
- 暖色坐标是唯一明显亮点；任何装饰不得与其争夺注意力。
- 页面隐藏或切到后台时停止非必要循环动画。

## 8. 动效规范

### 8.1 叙事焦点

信件到密码页是唯一重点动画：

1. 0–500ms：信件文字降低对比并退入夜色。
2. 500–1800ms：暖色锚点沿细轨迹移动，星点产生轻微视差。
3. 1800–2600ms：轨迹收拢并对齐密码区域。
4. 2600–3200ms：密码提示和输入区完成进入，立即可操作。

具体时长允许在实现时小幅校准，但总时长应保持约 3 秒，不能变成长时间不可操作的影片。

### 8.2 常规反馈

- 按钮按压和输入反馈：100–150ms。
- 首页、密码等常规状态切换：150–400ms。
- 密码成功到地图：约 800ms；密码圆点收拢为暖色坐标，地图由模糊灰蓝变清晰并由位置标记接住坐标。
- 退出快于进入，使用自然减速，不使用弹跳或橡皮筋曲线。

所有动效支持 `prefers-reduced-motion`。减少动态效果时取消长距离位移和视差，保留短暂的透明度、颜色和状态反馈。

## 9. 技术结构

保持无构建工具的静态前端与 Python 标准库服务器。建议职责拆分：

- `static/index.html`：访客体验壳和语义结构。
- `static/content.js`：公开、可编辑的文案配置。
- `static/theme.css`：颜色、字体、间距和通用状态令牌。
- `static/experience.css`：双入口、信件、过场和密码布局。
- `static/experience.js`：页面状态机、`letter_seen`、过场和密码交互。
- `static/map.html`：受保护地图的语义结构。
- `static/map.css`、`static/map.js`：地图视觉与现有刷新逻辑。
- `static/leaflet.css`、`static/leaflet.js`：保持现状。
- `app.py`：保留认证、限流、状态和静态文件服务，仅做新静态资源、搜索引擎屏蔽和必要路由适配。
- `static/owner.html`：不纳入视觉重构。

前端状态机至少包含：`entry`、`letter`、`transition`、`password-idle`、`password-submitting`、`password-error`、`password-success`。地图继续由独立受保护路由提供，不把定位数据写入公开页面。

## 10. 数据流与安全边界

1. 访客选择信件时只发生本地界面状态变化。
2. 完成阅读后本地写入 `letter_seen=true`。
3. 选择位置时，前端可调用现有 `/api/state` 判断是否仍有有效认证：200 进入地图，401 显示密码。
4. 密码通过 `POST /api/login` 发送；服务器验证后设置签名 Cookie。
5. `/map` 与 `/api/state` 继续要求有效 Cookie。
6. 地图每 10 秒读取位置状态，前端不发送访客坐标。

隐私与安全规则：

- 密码只在服务器环境中配置，前端不得包含或推导真实密码。
- 输入框使用密码语义，不记录输入值，不写入存储，不加入日志。
- 保留服务器每 IP 五次失败后等待 60 秒的限流。
- 第三次失败后的验证方式提示是用户明确要求的便利性设计，会降低口令猜测难度；限流仍然保留，但该位置入口不应被描述为高强度安全系统。
- 页面加入 `noindex`、`nofollow` 并提供禁止抓取的 `robots.txt`；这只能降低被索引概率，不能让公开信具备保密性。
- 不加入分析脚本、访客通知、地理定位请求或第三方追踪。

## 11. 错误和边界状态

- **密码不完整**：指出需要完整六位数字，不提交请求。
- **密码错误**：按客户端本次页面会话中的失败次数展示确认文案；刷新后个性化文案计数可以重置，服务器限流不受影响。
- **提交中**：锁定重复提交，保留视觉焦点。
- **429 限流**：显示服务器返回的剩余等待时间，到期后恢复输入。
- **登录网络失败**：保留已输入内容，显示重试操作。
- **未上报位置**：显示“正在等待共享人的手机上报位置”。
- **停止共享**：显示现有停止说明，并自动等待恢复。
- **位置过期**：超过 5 分钟未更新时明确标记为最后已知位置。
- **地图图块失败**：保留状态信息与坐标标记层，显示重试底图操作。
- **认证过期**：返回双入口首页并在选择位置后显示密码，不丢失 `letter_seen`。
- **配置正文或过场为空**：省略对应内容，不显示占位符、不产生多余滚动区。
- **配置文字较长**：允许自然换行和纵向滚动，不截断信件内容。

## 12. 可访问性与响应式

- 以手机为主要设计尺寸，支持至少 320px 宽度；桌面端限制阅读宽度并扩大留白。
- 地图在手机与桌面都占据主要可视区域，并适配安全区域边距。
- 使用语义标题、段落、按钮、链接和表单标签；不依赖可点击 `div`。
- 保持自然 Tab 顺序、可见焦点和 Enter 提交。
- 动态提示使用礼貌型 live region；真正阻断操作的错误使用 alert 语义。
- 在 200% 文本缩放下不重叠、不裁切、不丢失操作。
- 高对比模式下用文字或形状补充颜色状态。
- 高级动效不可用时，信件、密码输入和地图核心功能仍然可访问；JavaScript 完全不可用时至少保留信件内容和明确说明，不出现空白页面。

## 13. 验证计划

### 功能路径

- 首次访问：信件为主入口，位置入口可见。
- 阅读信件：正文空状态正确，结尾和继续操作存在，写入 `letter_seen`。
- 再次访问：位置成为主入口，信件仍可访问。
- 直接位置与信件后位置两条路线均可完成登录。
- 有效认证 Cookie 可直接进入地图；失效 Cookie 正确回到密码流程。
- 三档失败提示、统一成功提示、第五次限流和倒计时正确。

### 地图与网络

- 正常位置、未上报、停止共享、超过 5 分钟、认证过期、断网和图块失败。
- 刷新轮询不会重复创建地图、标记或定时器。
- 现有坐标转换、轨迹、电量和更新时间功能保持正确。

### 体验质量

- 320px 手机、常见手机、桌面和用户实际浏览器宽度。
- 键盘完整操作、粘贴六位数字、退格跳转和 Enter 提交。
- `prefers-reduced-motion` 下无长距离轨迹和视差，状态仍清楚。
- 200% 缩放、长正文、空正文、长过场文字和空过场文字。
- 实现完成后进行一次桌面与手机联合截图检查、一次集中修复和至多一次确认检查。

## 14. 验收标准

实现完成需同时满足：

- 四个确认过的体验阶段与“星野坐标”视觉方向一致。
- 所有已确认文案准确，正文与过场保持可编辑且默认为空。
- 双入口和 `letter_seen` 行为符合本规格。
- 位置密码仍由服务器验证，公开前端不包含密码。
- 现有定位、地图、停止共享和站主管理能力未被破坏。
- 关键错误、隐私说明、响应式、键盘和减少动态效果路径可用。
- 不存在访问通知、访客定位请求或分析追踪。
