# 视频上传规则（约定，请长期遵守）

用户（项目负责人）的说法是唯一入口：**他说"上传视频"，就按下面的流程走一遍。**

## 固定流程

1. **扫描文件夹**：`~/Desktop/上传视频forxcy/`（他往里拖视频，支持 mp4 / mov / m4v / webm）。
2. **先比对，不重复上传**：拿每个视频的**拍摄时间**（MP4/MOV 的 `moov/mvhd` 创建时间）和服务器
   `/opt/locapp/media/captions.json` 里已记录的 `recorded` 比对；命中就跳过。其次再用文件名数字比对兜底。
3. **只上传没上传过的**：压缩到适合网页播放的大小（540p；若码率仍偏高再降到 480p），
   命名规则：去掉 `IMG_` 前缀、扩展名统一 `.mp4`（例如 `IMG_0118.MOV` → `0118.mp4`）。
4. **写时间信息**：把原始拍摄时间写进 `captions.json` 的 `recorded`（压缩会丢掉原始时间戳，所以要单独记）。
5. **文字可选**，三种来源，优先级从高到低：
   1. 同名 txt（`IMG_0118.txt`）——单独补一条时用；
   2. 文件夹里的批量文案文件 `文案.txt`（一行一条：`文件名 | 文字`）——视频多时推荐；
   3. 文件名里的文字（`IMG_0118 太原的早晨真冷.MOV`）——最省事，直接改名即可。
   三者都没有 → 只显示时间（前端用 `recorded` 生成 `2026.10.4` 这样的日期）。
6. **收尾**：报告"新增了哪几条、跳过了哪几条、各自的时间与文字"，然后告诉他刷新页面查看。

## 执行方式

```bash
python3 tools/upload_videos.py --dry-run   # 只检查，不上传（先说清楚要做啥）
python3 tools/upload_videos.py             # 真正执行
```

## 数据结构

服务器 `/opt/locapp/media/`：

- `<名称>.mp4` —— 网页播放用的压缩版；
- `captions.json` —— 每个视频的说明与拍摄时间：

```json
{
  "clip-01.mp4": {
    "caption": "2026.10.4，这是一条示例说明文字",
    "recorded": "2026-10-04 16:40:43"
  }
}
```

本地备份：`work/media-captions.json`（每次更新后同步一份）。
